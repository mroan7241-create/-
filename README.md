# نظام متابعة توزيع الأجهزة — جمعية الزاد

تطبيق ويب على Google Apps Script، بالشراكة مع مؤسسة سليمان أبانمي الأهلية.

## الملفات

| الملف | الدور |
|---|---|
| `Code.gs` | الخادم: المصادقة، الصلاحيات، التعامل مع Google Sheets، العمليات |
| `Index.html` | الواجهة الكاملة: HTML + CSS + JavaScript (ملف واحد، بلا موارد خارجية عدا الخطوط) |
| `tools/verify.js` | فاحص ثابت: سلامة JS، توازن البنية، أنماط النشر الخطرة، مطابقة الاستدعاءات |
| `tools/smoke.js` | اختبار تشغيلي: يرسم كل شاشة لكل دور داخل DOM مبسّط |
| `tools/server-test.js` | اختبار منطق الخادم: التحقق، التنقية، الأمان، ثبات بنية الجداول، دورة اعتماد الجمعيات |
| `tools/perf-bench.js` | قياس تجريبي لعدد قراءات الشيت قبل/بعد تحسينات الأداء (لا يُنسخ للنشر) |
| `HANDOFF.md` | حالة المشروع الحالية، الأجزاء المكتملة والمتبقية، للجلسة القادمة |

مجلد `tools/` أداة تطوير فقط — **لا يُنسخ إلى مشروع Apps Script**. الملفان
الوحيدان اللذان يُنسخان فعليًا إلى Apps Script هما `Code.gs` و`Index.html`.

## تشغيل الفحوص

```bash
node tools/verify.js
node tools/smoke.js
node tools/server-test.js
```

يجب أن تنجح الثلاثة (فحص ثابت + تشغيلي + منطق خادم) قبل أي نشر.
`tools/perf-bench.js` أداة قياس اختيارية، ليست جزءًا من بوابة النجاح/الفشل.

## أصول الهوية البصرية

الشعاران يُحقنان من ثابت واحد في أعلى كتلة JavaScript داخل `Index.html`:

```js
var BRAND = {
  zadLogo: '',      // ضع هنا data URI لشعار جمعية الزاد المفرّغ
  partnerLogo: '',  // ضع هنا data URI لشعار مؤسسة سليمان أبانمي الأهلية المفرّغ
  partnerName: 'مؤسسة سليمان أبانمي الأهلية',
  partnerLabel: 'بالشراكة مع'
};
```

**شروط الأصول:**

- استخدم PNG بخلفية شفافة أو SVG. لا تستخدم صورة عليها خلفية بيضاء أو سوداء مدمجة.
- لا تقص الشعار ولا تغيّر نسبته ولا تضف إليه ظلًا أو حدًا أو لونًا.
- الصق القيمة كاملة بصيغة `data:image/png;base64,...` بين علامتي الاقتباس.

ما دام الحقلان فارغين، يعرض النظام **بديلًا نصيًا أنيقًا** بألوان الهوية بدل أي مربع أسود.
لا تظهر أي مساحة صلبة خلف أي شعار في الحالتين.

### تحويل ملف الشعار إلى Data URI

على ويندوز (PowerShell):

```powershell
"data:image/png;base64," + [Convert]::ToBase64String([IO.File]::ReadAllBytes("zad-logo.png")) | Set-Clipboard
```

على macOS أو Linux:

```bash
printf 'data:image/png;base64,%s' "$(base64 -w0 zad-logo.png)" | pbcopy
```

ثم الصق الناتج داخل `zadLogo` أو `partnerLogo`.
يمكن التحقق من أن الملف يحمل قناة شفافية فعلية عبر:

```bash
python3 -c "import struct,sys; d=open(sys.argv[1],'rb').read(); print('نوع اللون:', struct.unpack('>B', d[25:26])[0], '(6 أو 4 = يحمل شفافية)')" zad-logo.png
```

### شكل الـ Lockup

الزاد دائمًا في الصف الأول بوصفه الشعار الرئيسي، والشريك في صف مستقل تحته
يفصله خط رفيع هادئ مع عبارة «بالشراكة مع». لا يُدمج الشعاران في شكل واحد،
ولا يتكرر شعار الشريك بوصفه عنصرًا زخرفيًا في أي مكان آخر من الواجهة.

## قواعد لا تُخالَف

- لا تُشغّل `setupSheets()` على ملف يحتوي بيانات إنتاجية فعلية دون تأكّد —
  آمنة ومتكررة (لا تحذف ولا تكرر بيانات) لكنها خطوة يجب أن تكون واعية.
- لا تُغيّر عناوين أعمدة Google Sheets؛ الكود يقرأ بالاسم العربي حرفيًا.
- لا تُعِد تسمية `Index.html`؛ `doGet` يستدعيه بالاسم `'Index'`.
- لا تضع أي سر أو مفتاح داخل `Index.html` — الملف يصل إلى المتصفح كاملًا.
- لا تُشغّل أي دالة ترحيل (`migrateReferenceData`, `migratePhoneNumbers`)
  على نسخة إنتاجية دون تشغيل نسخة المعاينة القابلة للقراءة أولًا حين تتوفر
  (`previewPhoneNormalization` قبل `migratePhoneNumbers` مثلًا).

## التثبيت والتشغيل داخل Google Apps Script (من الصفر)

1. أنشئ Google Sheet جديدًا فارغًا (سيكون قاعدة البيانات).
2. من القائمة: الإضافات ← Apps Script (أو Extensions ← Apps Script).
   سيُفتح محرر Apps Script مرتبطًا تلقائيًا بهذا الملف.
3. احذف محتوى `Code.gs` الافتراضي، والصق محتوى `Code.gs` من هذا المستودع
   كاملًا حرفيًا.
4. من القائمة الجانبية في المحرر: أضف ملفًا جديدًا من نوع **HTML** باسم
   `Index` بالضبط (بلا امتداد `.html` في اسم الملف داخل المحرر — Apps
   Script يضيفه تلقائيًا). الصق فيه محتوى `Index.html` من هذا المستودع كاملًا.
5. احفظ المشروع (Ctrl/Cmd + S).
6. من قائمة الدوال أعلى المحرر اختر `setupSheets`، ثم اضغط ▶ تشغيل.
   في أول تشغيل سيطلب منك Google صلاحيات الوصول — وافق عليها (المشروع
   يطلب فقط صلاحية Google Sheets الخاصة بالملف نفسه).
7. افتح **سجل التنفيذ** (Executions، الأيقونة الشبيهة بالساعة على
   الشريط الجانبي الأيسر، وليست أدوات المطوّر F12 في المتصفح) وابحث عن
   السطر الذي يحتوي `بيانات المدير المؤقتة`. سيظهر بريد إلكتروني وكلمة
   مرور مؤقتة لأول حساب مدير — سجّل الدخول بهما فورًا ثم غيّر كلمة
   المرور من صفحة الإعدادات داخل النظام نفسه.
8. **النشر كتطبيق ويب**: من القائمة أعلى يمين المحرر اضغط **Deploy /
   نشر** ← **New deployment / نشر جديد** ← اختر النوع **Web app / تطبيق
   ويب**. اضبط:
   - Execute as: **Me / أنا** (صاحب المشروع).
   - Who has access: **Anyone / أي شخص** (ليتمكن أعضاء الجمعيات
     والمناديب من الدخول من خارج حساب Google الخاص بك؛ الوصول الفعلي
     محكوم بالكامل من داخل النظام عبر الأدوار وكلمات المرور، وليس عبر
     صلاحيات Google).
   - اضغط **Deploy / نشر**، ثم انسخ رابط تطبيق الويب الناتج وشاركه مع
     المستخدمين.
9. لأي تحديث لاحق على `Code.gs` أو `Index.html`: كرّر النشر عبر **Manage
   deployments / إدارة النشرات** ← تعديل النشرة القائمة ← إصدار جديد،
   بدل إنشاء نشرة جديدة، حتى يبقى الرابط نفسه ثابتًا لدى المستخدمين.

## تحديث نسخة قائمة فعليًا (وليس تثبيتًا من الصفر)

1. من الفرع `claude/code-index-review-kz5k4u` في هذا المستودع، انسخ محتوى
   `Code.gs` و`Index.html` كاملَين والصقهما فوق النسختين القائمتين في
   محرر Apps Script (استبدال كامل، لا دمج يدوي جزئي).
2. شغّل الفحوص الثلاثة محليًا (`node tools/verify.js` وما يليها) على
   نفس النسخة قبل اللصق للتأكد من عدم وجود كسر إن كنت عدّلت شيئًا يدويًا.
3. الميزات الإضافية الجديدة (طلبات الانضمام، المصادر المرجعية، عمودا
   الموقع الجغرافي في ورقة المستفيدين) تُنشئ أوراقًا أو أعمدة جديدة
   تلقائيًا فقط عند تشغيل `setupSheets` — وهي إضافية بالكامل ولا تمس أي
   عمود أو صف موجود في الأوراق الحالية. شغّلها مرة واحدة بعد كل تحديث
   يضيف ورقة أو عمودًا جديدًا.
4. أعد النشر عبر **Manage deployments ← New version** كما في الخطوة 9 أعلاه.

انظر `HANDOFF.md` لحالة المشروع التفصيلية الحالية: ما المكتمل والمختبر،
وما المتبقي، وأي ترحيل مكتوب لكنه غير مُشغَّل بعد.
